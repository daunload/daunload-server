# 크롬 확장프로그램으로 영상 직접 다운로드

영상 다운로드 경로는 `학교 CDN → 확장프로그램 다운로드 창 → PC 디스크`다. 서버는 본인 과목·공개 여부를 확인하고 Commons 메타데이터에서 영상 주소만 조회한다. 학교 로그인 비밀번호, 세션 쿠키, API 로그인 토큰은 확장프로그램으로 보내지 않는다.

## 운영자: 서비스 주소에 맞는 패키지 만들기

```bash
python3 scripts/build-download-extension.py https://daunload.cloud
```

`dist/ssu-downloader/`와 `dist/ssu-downloader.zip`이 생성된다. ZIP을 사용자에게 배포한다. 허용하는 웹사이트는 빌드할 때 지정한 원점 하나뿐이다. 다른 서비스 주소나 포트로 변경하면 다시 빌드하고 확장을 갱신해야 한다. 프로젝트 소스의 `extensions/ssu-downloader`도 `https://daunload.cloud` 운영용이다. 인자 없이 빌드해도 이 주소를 사용한다. localhost와 다른 도메인에는 연결되지 않는다.

개발 서버용 패키지:

```bash
python3 scripts/build-download-extension.py http://localhost:8000 --out dist/ssu-downloader-local
```

API·웹 코드를 함께 배포한다. DB 마이그레이션은 필요 없다. `ALLOW_VIDEO_RELAY=false`가 기본값이며 기존 영상 링크 발급과 `/downloads/{token}`의 영상 중계는 410으로 거절한다. 자료와 전사용 오디오 경로는 유지되므로 **이 기능들의 서버 트래픽과 오디오 변환 부하는 여전히 발생한다**. `ALLOW_VIDEO_RELAY=true`는 과거 클라이언트 호환을 위해 명시적으로 중계를 다시 켜는 설정이며, 새 웹은 이 설정과 무관하게 확장을 사용한다. 자동 중계 대체 경로는 없다.

## 사용자 설치와 이용

1. 운영자에게 받은 ZIP을 압축 해제한다.
2. 데스크톱 Chrome의 `chrome://extensions`에서 개발자 모드를 켠다.
3. **압축해제된 확장 프로그램을 로드합니다**에서 `manifest.json`이 있는 폴더를 선택한다.
4. 대시보드를 새로고침하고 영상의 **내려받기** 또는 **전체 받기**를 누른다.

내려받기를 누르면 새 탭 대신 독립된 팝업 창이 열린다. 크롬 툴바의 확장 아이콘으로도 열 수 있으며, 이미 열려 있다면 해당 창을 앞으로 가져온다. 다른 곳을 클릭해도 닫히지 않는다.

처음 열린 확장프로그램 다운로드 창에서 **저장 폴더 선택**을 누른다. 선택한 폴더에 저장하며 같은 이름은 `(1)`, `(2)`를 붙여 기존 파일을 보존한다. 폴더 권한을 취소하면 선택을 다시 요청할 수 있다. 별도 실행 파일이나 Python 설치는 필요 없다. 정식 일반 사용자 배포는 이 패키지를 바탕으로 Chrome 웹 스토어 등록·심사를 진행할 수 있으며, 현재 저장소 변경만으로 스토어에 게시되지는 않는다.

전체 받기는 선택한 영상의 주소를 2개씩 조회해 모두 확장 목록에 등록한다. 이미 등록한 영상의 다운로드 완료를 기다리지 않는다. 실제 파일 전송은 확장 전체에서 2개씩 진행하며, 나머지는 목록에 대기 중으로 표시한다. 취소·진행 상황은 확장프로그램 다운로드 창에서 확인한다. 전체 받기의 중지 버튼은 이 작업에서 시작한 다운로드를 취소한다. 중단 시 실패를 표시하고 새로 만든 미완료 파일을 정리한다. 자동 재시도·이어받기는 구현하지 않았으며 다시 시도하면 처음부터 받는다.

대시보드 탭을 닫아도 확장 목록에 등록된 영상은 대기 중인 항목까지 순서대로 저장할 수 있다. 다만 아직 주소를 조회·등록하지 못한 영상과 서버 완료 이력 기록은 중단된다. 전체 받기를 완료하려면 대시보드 탭과 다운로드 팝업 창을 모두 열어 둔다. 다운로드 창을 닫으면 해당 전체 받기도 중지되며 남은 영상을 자동으로 요청하지 않는다. 다시 전체 받기를 누르면 새 다운로드 창에서 폴더를 선택해 시작한다. 새 창에는 이전 창의 실패 목록을 표시하지 않는다. 다운로드 창을 새로고침하면 진행 중 전송이 중단된다. 서버의 ‘받음’은 확장 상태를 확인한 웹이 보고하는 기록이며, 서버가 사용자 디스크를 검증하는 것은 아니다. 완료 기록에 실패하면 파일 저장 성공과 기록 실패를 구분해 알린다. 과거 중계 방식에서 링크 발급 시 기록한 기존 이력은 그대로 남는다.

## 구현과 권한

- `POST /courses/{course_id}/videos/{item_id}/direct-download`: 수강 과목과 공개 상태 검증, 주소·파일명·완료 확인 토큰 반환.
- `POST /saved-videos/{id}/direct-download`: 소유권을 확인한 저장 주소 반환. 파일 존재 여부를 서버에서 미리 내려받아 검사하지 않는다.
- `POST /downloads/complete`: 현재 로그인과 완료 확인 토큰의 소유자·토큰 버전·유효기간을 검사한 뒤 기록. 토큰은 7일 유효하며 API 로그인이나 중계에 사용할 수 없다. 반복 보고 시 기존 다운로드 횟수는 증가할 수 있다.
- 확장 페이지에서 `fetch()` 응답 스트림을 File System Access API의 쓰기 스트림에 연결한다. `chrome.downloads` 요청에는 DNR 헤더 수정이 적용되지 않는 것을 실제 브라우저에서 확인했으므로 다운로드 관리자를 경유하지 않는다. 파일을 JavaScript Blob에 통째로 적재하지 않는다.
- `storage.session`에 작업 ID를 보관하여 서비스 워커가 재시작되어도 상태를 조회한다. 브라우저를 완전히 종료하면 웹 연동 작업 기록은 사라진다.
- `declarativeNetRequest`는 확장 자체가 시작한 학교 도메인 요청에만 `Referer`·`Origin`을 붙이고, 학교 도메인 밖으로 나가는 HTTP(S) 요청은 차단한다. 일반 학교 브라우징에는 적용하지 않는다.
- HTTPS 학교/CDN 주소, 파일명, 메시지 발신 웹사이트·탭을 검증한다. 전체 인터넷 호스트 권한이나 학교 쿠키 읽기 권한은 요구하지 않는다.

## 검증

```bash
.venv/bin/pytest tests/test_direct_downloads.py tests/test_downloads.py tests/test_media.py tests/test_materials_api.py -q
.venv/bin/pytest tests/test_videos_web.py -q
# Playwright Chromium 설치가 필요하다 (일반 Chrome은 커맨드라인 확장 로드를 제한할 수 있음).
.venv/bin/playwright install chromium
.venv/bin/pytest tests/test_download_extension.py -q
```

이미 설치된 테스트용 Chromium을 지정하려면 `PLAYWRIGHT_CHROMIUM_EXECUTABLE`에 실행 파일 경로를 설정한다. 확장 테스트는 임시 프로필·로컬 HTTPS 모의 CDN을 사용한다. 외부 학교 파일이나 계정은 필요 없다.

운영 적용 전 실제 계정으로 짧은 영상 하나를 받아 확인한다. 학교 CDN 정책, 실주소의 리다이렉트, 서명 만료 등은 모의 테스트만으로 확정할 수 없다. 확인 항목은 파일 열기, 다운로드 경로, 중지, 전체 받기, 확장프로그램의 다운로드 완료, 서버 로그에 `/downloads/{token}` 영상 요청이 없는지다.


## 1.2.1 업데이트 적용

팝업 로딩 중 중복 생성, 종료 후 전체 받기 계속 실행, 이전 실패 이력 혼합을 수정했다. 웹과 확장프로그램을 함께 업데이트해야 한다.

1. 최신 코드로 API/웹을 다시 배포한다. 로컬 Compose 사용 시 `docker compose up -d --build api`.
2. 열려 있는 다운로드 창을 닫고 `chrome://extensions`에서 **다시 로드**를 누른다(버전 1.2.1 확인).
3. 대시보드를 강력 새로고침한 뒤 **전체 받기**를 실행한다.

확장 내부에서는 팝업 생성 시 고유 식별자를 발급하고, 전체 받기의 모든 요청이 같은 식별자를 사용한다. 이전 창의 작업 결과는 대시보드의 종료 확인을 위해 일시 보관하되 새 창에서는 조회·실행하지 않는다.


## 1.2.2 업데이트

전체 받기에서 선택한 모든 영상을 목록에 등록하도록 수정했다. 4개를 선택하면 4개가 표시되고, 저장은 2개씩 진행한다. 웹과 확장 패키지를 함께 갱신한 뒤 대시보드를 강력 새로고침한다. 창 종료 시 대기 중인 항목까지 중단하는 동작은 유지한다.


## daunload.cloud 연결 (1.2.3)

`dist/ssu-downloader`의 확장을 다시 로드하고 `https://daunload.cloud/` 대시보드를 강력 새로고침한다. 다른 경로의 확장을 설치했다면 새 ZIP으로 해당 폴더를 갱신하거나 이 폴더를 다시 등록한다. 확장 상세 정보에서 버전 1.2.3과 사이트 접근 허용 상태를 확인한다.

운영 서버에는 현재 웹 코드와 직접 다운로드 API도 반영되어 있어야 한다. 확장 패키지 생성은 서버 배포를 수행하지 않는다. 대시보드의 `POST .../direct-download`가 성공하고 확장 팝업이 열리면 연동된 것이다. `POST .../download-link`와 영상 `GET /downloads/{token}`이 보이면 운영 서버/브라우저의 웹 코드가 이전 버전이다.


## 1.2.4 디자인 변경

이름을 ‘아유 하기싫어 다운로더’로 바꾸고 다운로드 창 디자인과 아이콘을 교체했다. 기능과 권한은 그대로다. 새 패키지를 빌드해 확장을 갱신한다.

## 1.2.5 뚱이 테마

아이콘과 빈 화면 그림을 뚱이 사진으로, 색을 비키니시티 테마로 바꿨다. 기능과 권한은 그대로다. 새 패키지를 빌드해 확장을 갱신한다.
