# 관리자 대시보드 설계

작성일: 2026-11-05 · 대상: `app/web`, `app/api/routes_admin.py`, `app/db`

## 1. 목적

지금 어드민은 사용자 카드 목록이라 서비스가 얼마나 쓰이는지, 어디에 문제가 있는지 알 수 없다. 운영자가 다음 세 가지를 한곳에서 할 수 있어야 한다.

1. 사용자 활동량을 지표로 본다.
2. 누가 무엇을 했는지 한눈에 본다.
3. 어떤 영상에서 언제 왜 실패했는지 등 문제를 확인한다.

운영자의 표현: "디비에 저장된 내용을 최대한 다양하게 조회하고 싶다", "유저의 모든 데이터를 쉽게 볼 수 있어야 한다".

## 2. 목표와 비목표

**목표**
- `#admin` 화면을 탭 4개(현황, 사용자, 활동, 문제)로 된 대시보드로 교체한다.
- 사용자 목록과, 한 사용자의 기록을 모두 볼 수 있는 상세 화면을 만든다.
- 로그인과 다운로드를 날짜별로 새로 기록해 활동 추이를 낸다.

**비목표**
- **수정·편집 기능은 만들지 않는다.** 운영자가 "바꾸고 싶은 데이터는 없다"고 확인했다. 어드민은 조회 전용이고 새 API는 모두 GET이다. 일별 기록 삭제는 워커만 한다.
- 재시도, 강제 동기화, 사용자 대신 실행하기.
- 관리자별 권한 등급과 관리자 조회 감사 로그.
- 현재 접속 여부(실시간), CSV 내보내기.

**이렇게 되면 실패다**
- 비밀번호, 세션, 토큰, 전사 본문이 응답이나 화면에 나온다.
- 일반 사용자가 어드민 API나 데이터에 닿는다.
- 어드민 조회 때문에 일반 사용자 화면이 느려진다.

## 3. 결정 사항

### 운영자가 정한 것
- **디자인:** 시안 A. 지금 사이트 테마(먹선, 하늘색 배경, 분홍 강조)를 유지한다. 시안은 `.superpowers/brainstorm/64291-1793871100/content/`의 `admin-direction.html`(A안), `admin-users.html`이다.
- **전사:** 본문은 보지 않는다. 제목, 과목, 모델, 길이, 저장 시각만 보여 준다.
- **과제 점수:** 보여 주지 않는다. 출석과 제출 상태는 보여 준다.
- **활동 기록:** 로그인과 다운로드를 사용자·날짜별 합계로 새로 기록한다. 건별 이벤트는 남기지 않는다.

### 설계자가 정했고 운영자가 반대하지 않은 것
- **보여 주지 않는 데이터:** `password_hash`, `password_enc`, `session_enc`, `target_enc`, `token_version`, `media_url`, `PlaybackJob.video`, `Transcript.text`, `Transcript.segments`, `AssignmentRow.score`, `AssignmentRow.points_possible`.
- **일별 기록 보관:** 90일. 지난 기록은 워커가 지운다.

### 설계자 판단 (운영자 확인 전)
- 날짜 경계는 한국 시간(Asia/Seoul)이다.
- 기간 선택은 7일(기본), 30일, 90일이다.
- 상세 화면의 전체 타임라인은 기존 `/activities` API를 확장해 쓴다.
- **자동 재생은 사용자 활동이 아니다.** 활동 사용자의 "재생 시작"에서 `scope="auto"` 묶음을 뺀다. 재생한 강의 수에는 포함하되 그중 자동 재생 수를 함께 적는다.
- **다운로드는 숫자 하나로 합친다.** 영상 직접 저장은 완료 보고 시점, 나머지와 수업자료는 링크 발급 시점에 기록되므로 설명은 "완료 보고 또는 링크 발급 횟수"로 쓴다. 나눠 보는 것은 범위에 넣지 않는다.

## 4. 데이터

### 새 테이블 `user_daily_activity`
| 컬럼 | 형식 | 설명 |
|---|---|---|
| `user_id` | FK users, `ondelete=CASCADE` | 계정 삭제 시 함께 삭제 |
| `day` | date | 한국 시간 기준 날짜 |
| `logins` | int, 기본 0 | 사이트 로그인 성공 횟수 |
| `downloads` | int, 기본 0 | `record_download` 호출 횟수 |

- 기본 키는 `(user_id, day)`, `day`에 인덱스를 둔다. 값 증가는 upsert로 한다(Postgres와 테스트용 SQLite 모두 동작해야 한다).
- `_record_login()`(`routes_account.py`)과 `record_download()`(`services/downloads.py`)에서 같은 트랜잭션으로 올린다.
- arq 워커에 하루 한 번 도는 cron을 추가해 90일이 지난 줄을 지운다.
- Alembic 마이그레이션을 추가한다. 과거 데이터는 채우지 않는다.

### 지표 정의
기록 시작 전 기간은 비어 있으므로, 화면에 "로그인·다운로드 추이는 YYYY-MM-DD부터 집계"라고 쓴다(첫 기록 날짜 기준).

| 지표 | 정의 |
|---|---|
| 활동 사용자 | 기간 안에 로그인, 다운로드, 재생 시작, 전사 저장 중 하나라도 한 사용자 수(중복 제거) |
| 전체 사용자 | `users` 전체 수 |
| 재생한 강의 | 기간 안에 `finished_at`이 있고 `status=done`인 job 수와 `duration` 합 |
| 다운로드 | `user_daily_activity.downloads` 합. 표시 이름은 "다운로드 기록"이며 실제 저장 완료를 뜻하지 않는다는 설명을 붙인다 |
| 재생 실패 | 아래 "재생 실패의 정의"를 따른다. 실패율은 `실패 / (done + 실패)` |

### 재생 실패의 정의
현황, 사용자, 문제 탭이 모두 같은 정의를 쓴다.
- `status`가 `failed` 또는 `locked`인 job이다. 제품도 둘을 실패로 집계한다.
- **시도한 영상만 센다.** 묶음이 중단되면 남은 job이 시도 없이 `failed`가 되고 `finished_at`도 비어 있다(`services/playback.py`). `started_at`이 없는 job은 실패 수와 실패율에서 빼고, 묶음 오류 한 줄에 "미실행 N개"로 보여 준다.
- 실패 시각은 `finished_at`, 없으면 묶음의 `finished_at`을 쓴다.

### 문제 시각 기록
LMS 오류와 영상 주소 확보 실패에는 발생 시각이 저장되지 않는다. 1단계에서 `LmsCredential.last_error_at`, `SavedVideo.resolve_failed_at`을 추가하고 값을 쓰는 코드(`services/lms_access.py`, `worker/main.py`, `services/saved_videos.py`)를 고친다. 오류가 풀리면 함께 비운다. 과거 값은 채우지 않는다.

- 시각이 없는 기존 줄은 "시각 기록 없음"으로 표시한다.
- LMS 문제는 현재 상태이므로 기간과 관계없이 문제 탭에 넣는다.
- 영상 주소 확보 실패는 다시 시도되지 않는 영구 오류가 많아, `resolve_failed_at`이 기간 안에 있는 것만 문제 탭에 넣는다. 나머지는 사용자 상세의 저장 영상 탭에서 볼 수 있다.

## 5. 화면

공통: 탭 상태는 주소에 둔다(`#admin/overview`, `#admin/users`, `#admin/users/{학번}`, `#admin/activity`, `#admin/problems`). 뒤로 가기가 동작해야 한다. 어드민 화면은 넓게 쓰도록 본문 최대 폭을 다른 화면보다 넓힌다.

### 현황
시안 A 그대로. 지표 카드 4개(활동 사용자, 재생한 강의, 다운로드 기록, 재생 실패) → 일별 그래프 + 최근 활동 → 최근 문제 표. 그래프는 일별 재생 완료, 로그인, 다운로드를 고를 수 있고 외부 차트 라이브러리 없이 HTML/CSS로 그린다. 표 형태 대안(스크린 리더용)을 함께 둔다.

### 사용자
학번 검색, LMS 상태 필터, "문제 있음만" 필터, 정렬(최근 활동, 가입일, 학번), 페이지 이동. 표 열은 학번, 최근 로그인, LMS 상태, 과목 수, 재생 완료/실패, 다운로드 수, 전사 수, 알림 채널이다. 줄을 누르면 상세로 간다.

"문제 있음"은 LMS 상태가 `ok`가 아니거나, 최근 7일 안에 4장 정의의 재생 실패가 있는 사용자다.

### 사용자 상세
머리: 학번, 가입일, 로그인 횟수, 최근 로그인, 이용 동의 시각, 관리자 여부, LMS 상태. 요약 숫자: 수강 과목, 남은 할 일, 재생 완료, 재생 실패, 다운로드.

| 탭 | 보여 주는 내용 |
|---|---|
| 전체 타임라인 | 재생, 다운로드, 전사를 시간순으로 |
| 과목·출석 | 과목명, 교수, 현재 학기 여부, 자동 재생, 주차별 출석 |
| 할 일·과제 | 할 일(종류, 제목, 마감, 완료 여부)과 과제(제출 상태, 제출 시각, 마감, 미제출 여부) |
| 재생 | 묶음(범위, 상태, 개수, 생성·시작·종료, 오류)과 그 안의 영상(제목, 길이, 상태, 시도 횟수, 진행, 시작·종료, 오류) |
| 다운로드 | 제목, 종류, 횟수, 처음·마지막 시각 |
| 저장 영상 | 제목, 과목, 주차, 파일명, 길이, 용량, 주소 확보 여부, 확보 실패 사유, 확보 시각 |
| 전사 | 제목, 과목, 모델, 길이, 생성·수정 시각 |
| 알림 | 채널 종류, 사용 여부, 등록일, 발송 기록(key, 시각) |
| LMS | 상태, 마지막 오류, 마지막 로그인·동기화, 다음 동기화 |

긴 목록은 각 탭에서 페이지를 나눈다. 재생 탭에는 상태, 과목, 기간 필터를 둔다.

### 활동
전체 사용자의 활동을 시간순으로 본다. 필터: 종류(재생, 다운로드, 전사), 학번, 기간. 학번을 누르면 상세로 간다.

### 문제
문제를 한곳에 모은다. 필터: 종류, 학번, 과목, 기간. 표: 시각, 사용자, 과목·영상, 종류, 오류 내용.

| 종류 | 출처 |
|---|---|
| 재생 실패 | 4장의 정의를 따르는 job과 그 `error` |
| 재생 묶음 오류 | `PlaybackBatch.error`. 묶음당 한 줄 |
| LMS 문제 | `LmsCredential.status != ok`, `last_error` |
| 영상 주소 확보 실패 | `SavedVideo.resolve_error` |

탭의 숫자는 위 네 종류를 합한 건수이고, 현황의 재생 실패 카드는 첫 줄만 센다. 두 숫자가 다를 수 있으므로 시안과 달리 탭 이름 옆 숫자에 "문제"라고 명확히 쓴다.

## 6. 보안과 개인정보

- 모든 새 API는 `AdminUser` 의존성과 `Cache-Control: no-store`를 쓴다. 조회 전용이다.
- 응답 모델은 필드를 직접 나열한다. 3장의 제외 필드가 들어가지 않는지 테스트한다.
- **오류 내용을 보여 주되 정리해서 내보낸다.** 기존 오류 문자열은 `str(e)`로 저장돼 주소나 토큰이 섞일 수 있다. 서버에서 URL의 쿼리와 경로를 지우고 길이를 2000자로 자른 뒤 반환한다. 이 처리는 응답에서만 하고 저장값은 건드리지 않는다.
- `/admin/users/{id}/activities`는 현재 오류를 반환하지 않는다는 테스트가 있다. 타임라인은 이 동작을 유지하고, 오류는 재생·문제 탭의 정리된 값으로만 본다.
- 화면에 넣는 모든 서버 문자열은 `esc()`로 처리한다.
- **개인정보처리방침을 먼저 고친다.** 지금 방침은 범위와 목적이 확장프로그램과 다운로드 연동으로 한정돼 있다. `privacy.html`을 웹서비스 전체로 넓히고, 일별 활동 기록(항목, 목적, 90일 보관, 계정 삭제 시 삭제)과 운영자가 문제 확인을 위해 이용·출석·제출 기록을 열람할 수 있다는 점을 적고 시행일을 고친다. 스토어 제출 자료(`store-assets/chrome-web-store/privacy-practices.md`)도 맞춘다.
- **서비스 안에서 한 번 알린다.** 방침이 약속한 대로, 변경 내용을 로그인한 사용자에게 한 번 보여 주고 닫으면 다시 보이지 않게 한다. 재동의는 받지 않는다(설계자 판단. 법률 검토는 받지 않았다).
- 일별 기록은 위 두 가지와 같은 배포 또는 그 이후부터 쌓는다.

## 7. 성능

- 집계는 어드민 요청 때만 계산한다. 별도 캐시나 집계 테이블은 처음에는 두지 않는다.
- 기간 조건에 쓰는 재생 시각(`finished_at`, `started_at`)에 인덱스가 필요한지 확인하고, 필요하면 마이그레이션에 넣는다.
- 목록은 모두 서버에서 페이지를 나눈다. 사용자 목록의 건수 열은 N+1이 없도록 한 쿼리나 묶음 쿼리로 구한다.

## 8. 제약

- 순수 HTML/CSS/JS, 빌드 도구와 프론트 의존성을 추가하지 않는다. 어드민 코드는 `app/web/admin.js`로 분리한다. `index.html`의 다른 정적 파일과 같은 방식으로 불러와 버전 해시가 붙게 한다.
- `design-system/MASTER.md`를 따른다. 44px 터치 영역, 색 토큰, SVG 아이콘, 가로 스크롤 금지. 디자인 규칙에 어드민 절을 추가한다.
- 모바일에서는 표를 카드 형태로 바꾸거나 표 안에서만 가로로 스크롤한다. 어드민은 PC 사용이 중심이지만 375px에서도 볼 수 있어야 한다.
- 빈 상태, 로딩 스켈레톤, 오류와 재시도를 탭마다 갖춘다.

## 9. 테스트

- API: 비로그인 401, 일반 사용자 403, 필터·페이지, 지표 계산, 제외 필드, 오류 정리, 계정 삭제 시 일별 기록 삭제, 90일 정리.
- SQLite 테스트와 별도로 **집계·UNION 쿼리를 Postgres에서 실행해 확인한다**(`tests/test_queue_postgres.py` 방식). 현재 CI는 Postgres에서 돌지 않는다.
- 브라우저: 탭 이동과 뒤로 가기, 검색·필터, 상세 탭, 문제 표, XSS 문자열, 375·1440px 가로 스크롤 없음.

## 10. 작업 순서

1. 개인정보처리방침과 서비스 안내, 일별 기록 테이블과 기록 코드, 오류 시각 컬럼. 지표는 기록이 쌓여야 의미가 있으므로 먼저 배포한다.
2. 어드민 API.
