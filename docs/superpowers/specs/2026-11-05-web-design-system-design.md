# 웹 디자인 시스템과 사용성 개선 설계

작성일: 2026-11-05
대상: `app/web` (대시보드 웹사이트)

## 1. 의도

사용자가 이 사이트의 UX가 불편하다고 느꼈고, 사용 편의성을 높이기를 원한다. 사용자가 세운 기준은 **"버튼을 본 순간 어떤 동작인지 예측할 수 있어야 한다"**이다.

따라서 이 작업의 디자인 시스템은 색과 폰트를 새로 고르는 작업이 아니다. 버튼, 확인, 진행 상황, 크기의 규칙을 정해서 화면마다 다른 동작 방식을 통일하는 작업이다.

사용자가 답답하게 느낀 순서는 다음과 같다.

1. 휴대폰에서 누르기와 읽기가 어렵다.
2. 진행 상황을 보는 곳이 흩어져 있다.
3. 확인 절차가 제각각이다.

## 2. 목표

- 휴대폰에서 글자를 읽고 버튼을 누르기 쉽게 만든다.
- 재생, 다운로드, 전사 진행 상황을 한곳에서 보고 제어하게 한다.
- 실수하면 곤란한 동작의 확인 방식을 통일한다.
- 버튼 문구와 모양만으로 범위와 결과를 알 수 있게 한다.
- 위 규칙을 문서와 재사용 가능한 CSS·JS로 남겨, 새 화면도 같은 규칙을 따르게 한다.

## 3. 비목표

- 뚱이 콘셉트, 색상, Pretendard·Black Han Sans 글꼴 변경 (`ui-ux-pro-max`가 추천한 인디고 색상과 Baloo 2·Comic Neue 조합은 쓰지 않는다)
- 프런트엔드 프레임워크, 빌드 도구, Tailwind 도입
- 서버 API와 재생·다운로드 동작 자체의 변경
- 메뉴 구조 개편이나 화면 통합
- 크롬 확장 프로그램 관리 창의 디자인 변경 [작성자 판단]

## 4. 실패로 보는 경우

기능이 동작해도 다음에 해당하면 실패다.

- 자주 쓰는 동작을 `⋯` 같은 메뉴에 숨겨 한 번에 누를 수 없게 된다.
- 한 화면에 보이는 강의 수가 크게 줄어든다.
- 진행 패널이 목록의 마지막 항목이나 버튼을 가려서 누를 수 없게 된다.
- 내려받기처럼 자주 쓰는 동작에 확인 창이 끼어든다.
- 사이트의 뚱이 말투가 사라져 평범한 관리 도구처럼 보인다.
- 버튼이나 오류 문구가 농담 때문에 뜻이 모호해진다.

## 5. 사용자가 정한 내용

### 5.1 휴대폰 목록: 시안 A, 크게 키우기

선택 이유는 **한 화면에 보이는 강의 수가 더 많고, 원하는 버튼을 한 번에 누를 수 있기 때문**이다.

- 목록의 구조는 크게 바꾸지 않는다.
- 제목은 16px, 보조 정보는 14px로 한다.
- 버튼 높이는 44px로 한다.
- 버튼이 많으면 다음 줄로 넘긴다. `⋯` 메뉴는 쓰지 않는다.

### 5.2 진행 상황: 시안 B, 하단 플로팅 바 + 시트

- 작업이 있으면 화면 아래에 `작업 3개 진행 중 · 실패 1개` 같은 요약 바를 보여 준다.
- 바를 누르면 시트가 올라와 작업별 진행률과 중지, 다시 시도 버튼을 보여 준다.
- 실패한 작업은 사용자가 다시 시도하거나 닫을 때까지 남긴다.
- 작업별로 탭을 닫아도 되는지 알려 준다. 재생은 서버에서 계속되고, 다운로드와 전사는 탭을 열어 두어야 한다.
- 진행 상황 제어는 이 패널로 모은다. 기존 표시는 다음과 같이 정리한다.
  - 첫 화면: `강의 재생 중 2/5개` 같은 요약만 남기고, 중지 버튼은 없앤다.
  - 강의 재생 화면: 영상별 상세 목록을 유지한다.
  - 내려받기 화면: 진행 표시(`#bulk-status`)를 없앤다.

### 5.2.1 휴대폰에서 쓸 수 없는 다운로드

영상 다운로드와 수업자료 전체 받기는 휴대폰에서 쓸 수 없다. 버튼은 비활성으로 보여 주고, 화면 위쪽에 `PC 크롬에서 받을 수 있어요` 안내를 한 번만 보여 준다. 줄마다 설명을 넣지 않는다.

### 5.2.2 하단 광고

AdSense 앵커 광고가 켜져 있는지는 사용자도 확실하지 않다. 켜져 있어도 진행 바가 가려지지 않게 구현하고, 실제 사이트의 휴대폰 화면에서 겹침을 확인한다.

### 5.3 확인 방식: 시안 C, 화면 가운데 창

PC와 휴대폰 모두 같은 모양의 가운데 창을 쓴다. 창에는 하는 일, 범위, 예상 시간, 필요한 경고를 보여 준다.

| 구분 | 동작 | 방식 |
|---|---|---|
| 바로 실행 | 내려받기, 전사(텍스트로 변환), 동기화, 테스트 메시지 | 확인 없이 실행 |
| 확인 후 실행 | 강의 일괄 재생, 재생 중지, 알림 채널 삭제, 전사본 삭제 | 가운데 창에서 한 번 확인 |
| 강한 확인 | 계정 삭제 | 가운데 창 + 지워지는 내용 안내 + 학번 입력 |

### 5.4 버튼 종류

| 종류 | 용도 | 모양 |
|---|---|---|
| 주요 동작 | 화면에서 가장 중요한 일 하나 | 분홍 배경, 먹선 그림자 |
| 일반 동작 | 사이트 안에서 바로 실행 | 흰 배경, 먹선 테두리, 필요하면 아이콘 |
| 사이트 밖으로 이동 | 새 탭 열기 | 일반 모양 + 새 탭 아이콘 |
| 위험한 동작 | 삭제, 재생 중지 | 빨간 글자와 테두리, 가운데 창으로 확인 |

### 5.5 이름 변경

| 지금 | 변경 후 |
|---|---|
| 강의 N개 한 번에 듣기 | 이번 주 강의 N개 재생 |
| 모두 재생 (N개) | 전체 강의 N개 재생 |
| 미리보기 | 재생 계획 보기 |
| 제출하기 | LMS에서 제출 + 새 탭 아이콘 |
| 새로고침이나 하자 | LMS 동기화 |
| 목록 새로고침 | 목록 다시 불러오기 |
| 전사 / 전체 전사 | 텍스트로 변환 |
| 전체 받기 (N) | 3주차 N개 내려받기 (실제 주차 이름 사용) |
| 중지 | 재생 중지 |
| 메뉴: 영상 재생 | 강의 재생 |
| 메뉴: 강의 영상 | 내려받기·텍스트 변환 |
| 요약 카드의 ↗ | › |

### 5.6 말투

- **뚱이 말투 유지:** 제목, 빈 화면, 로딩
- **분명하게 작성:** 버튼, 오류, 경고

## 6. 제약

- 현재 구조인 순수 HTML, CSS, JavaScript를 유지한다. 화면은 JS 문자열 템플릿으로 그린다.
- 다음 기능은 그대로 동작해야 한다.
  - 다운로드와 전사는 탭이 열려 있어야 진행된다.
  - 재생은 서버에서 진행되고 5초 간격으로 상태를 갱신한다.
- 일괄 재생 확인 창에는 범위와 관계없이 학칙 경고를 넣는다.
- 기존 접근성을 유지한다. 스킵 링크, `:focus-visible`, `prefers-reduced-motion`, `aria-*`가 해당한다.
- 브라우저 테스트가 버튼 이름에 의존한다. 이름을 바꾸면 `tests/test_week_web.py`, `tests/test_videos_web.py` 등의 테스트도 함께 고친다.
- `README.md`, `docs/chrome-download-extension.md`의 버튼 이름도 함께 고친다.

## 7. 구현 담당자에게 맡기는 내용과 작성자 판단

아래는 사용자와 합의한 내용이 아니라 작성자의 판단이다.

### 7.1 전체 적용

- PC에도 같은 글자 크기와 버튼 규칙을 적용한다. PC에서는 공간이 넓으므로 버튼을 오른쪽 한 줄에 둔다.
- 글자 크기는 12, 14, 16, 18, 22px과 제목용 `clamp` 크기로 줄인다. 12px은 배지처럼 보조적인 곳에만 쓴다. 본문과 버튼에는 쓰지 않는다.
- `.btn.small`과 `.btn.link`도 터치 영역을 44px로 맞춘다. 캘린더 이전·다음 버튼처럼 공간이 좁은 곳도 터치 영역은 44px을 유지한다.
- `app/web/style.css`에서 `.btn`이 두 번 정의된 부분을 하나로 합친다. `:root`에 글자 크기, 간격, z-index 토큰을 추가한다.

### 7.2 진행 패널

- 작업이 없으면 바를 숨긴다. 바가 떠 있으면 본문 아래에 여백을 더해 마지막 항목이 가려지지 않게 한다.
- PC에서는 지금 전사 패널이 있는 오른쪽 아래에 작은 패널로 보여 준다. 기존 `#transcribe-panel`은 이 패널로 대체한다.
- 실패 처리는 작업별로 다르게 한다.
  - 전사: 기존 `data-tx-retry` 동작으로 다시 시도한다.
  - 다운로드: 실패한 항목을 보관해 다시 시도할 수 있게 한다. 지금은 오류 문구만 보관한다.
  - 재생: 서버에 개별 재시도 기능이 없으므로 `다시 시도` 대신 `실패 사유 보기`로 강의 재생 화면을 연다. 닫은 묶음의 ID는 `localStorage`에 저장한다.
- 다운로드와 전사의 실패 기록은 지금처럼 메모리에만 두며, 페이지를 새로고침하면 사라진다.
- 패널에 넣는 다운로드는 여러 개 받기만이다. 단일 영상은 지금처럼 버튼에 진행 상태를 표시하고, 실패하면 닫을 때까지 남는 오류 토스트를 쓴다. 단일 수업자료는 완료 시점을 알 수 없어 패널에서 제외한다. 바의 작업 수는 패널에 있는 작업만 센다.
- 실행 중인 재생 묶음은 자동 수강을 포함해 모두 패널에 보여 주고 중지할 수 있게 한다.
- 패널에 남기는 재생 실패는 끝난 지 7일 이내이면서 실패한 영상이 있는 묶음이다. 사용자가 취소만 한 묶음은 제외한다. 닫은 기록은 브라우저별로 저장하므로 다른 기기에서는 다시 보일 수 있다.
- 다운로드와 전사의 중지는 확인 창 없이 바로 실행하고, 빨간색을 쓰지 않는 일반 버튼으로 둔다. 이름은 `다운로드 중지`, `변환 중지`로 한다.

### 7.3 확인 창

- `<dialog>`와 `showModal()`로 공통 함수를 만든다. 이미 전사 결과 창에서 쓰는 방식이다.
- `Esc`나 취소로 닫을 수 있고, 닫으면 포커스를 원래 버튼으로 돌려준다. 첫 포커스는 취소 버튼에 둔다.
- 확인 버튼에는 `8개 재생 시작`, `알림 채널 삭제`처럼 결과를 적는다.
- 이번 주 재생과 전체 재생의 확인 방식을 이 창으로 통일한다. 기존 제자리 확인(`week.confirming`)과 계정 삭제의 두 번 누르기는 제거한다.
- `재생 계획 보기`를 거치는 재생은 그 화면이 이미 확인 단계이므로 창을 한 번 더 띄우지 않는다. 대신 그 화면에 같은 학칙 경고를 넣는다.
- 계정 삭제의 학번 입력은 입력값이 일치할 때만 삭제 버튼을 활성화한다.
- 전사본 삭제는 전사 결과 창 위에서 확인 창을 연다.

### 7.4 공통 피드백

처음 정리한 문제 중 아래 내용도 함께 처리한다. 진행 패널과 확인 창 외의 항목은 이번 범위의 후순위다.

- 오류 토스트는 자동으로 사라지지 않고, 닫기 버튼을 둔다. 성공 토스트는 지금처럼 3.2초 뒤 사라진다.
- 확장 프로그램이 없어 다운로드에 실패하면 토스트 대신 설치 안내를 펼쳐서 보여 준다.
- 비활성 버튼의 이유는 `title`에만 두지 않고 버튼 근처에 글자로 보여 준다.
- 비동기 동작 버튼에는 처리 중 상태를 표시한다. 목록 로딩에는 스켈레톤을 쓴다.

### 7.5 산출물

- 규칙 문서: `design-system/MASTER.md`. 위 규칙과 토큰, 버튼 사용법을 담는다. `ui-ux-pro-max`의 `--persist` 위치와 같지만, 도구가 생성한 내용을 그대로 쓰지 않고 이 설계에 맞춰 작성한다.
- 페이지별 예외가 생기기 전에는 `design-system/pages/`를 만들지 않는다.

## 8. 완료 확인

- 375, 768, 1024, 1440px에서 가로 스크롤이 없고 진행 패널이 내용을 가리지 않는다.
- 휴대폰 크기에서 모든 버튼의 터치 영역이 44px 이상이다.
- 375×812px의 `강의 영상` 화면에서, 진행 바가 없고 목록까지 스크롤했을 때 강의 줄이 4개 이상 보인다. 버튼이 2개인 줄은 버튼이 한 줄에 들어간다. 버튼이 3개인 줄만 두 줄로 넘어갈 수 있다.
- 이번 주·전체 일괄 재생, 재생 중지, 알림 채널 삭제, 전사본 삭제, 계정 삭제가 모두 같은 확인 창을 거친다. `재생 계획 보기`를 거치는 재생은 그 화면에서 학칙 경고를 보여 준다.
- 키보드만으로 진행 패널과 확인 창을 조작할 수 있다.
- 기존 테스트를 새 이름에 맞게 고친 뒤 통과하고, 진행 패널과 확인 창의 브라우저 테스트를 추가한다.
- 실제 사이트에서 로그인 화면과 주요 화면을 브라우저로 확인한다.
- 실제 사이트의 휴대폰 화면에서 진행 바와 하단 광고가 겹치지 않는지 확인한다.
